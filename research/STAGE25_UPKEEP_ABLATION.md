# Stage 2.5: old PPO with heuristic upkeep

Base: `ad68a58f64d93c305ecdf97f5b32101fc0223e16` on
`codex/no-empty-animal-housing`. Experiment branch:
`codex/stage25-upkeep-ablation`.

## Question and scope

Does replacing manager care/fertilizer allocations improve an unchanged trained
PPO manager? No retraining, delta actions, autoregressive decoder, new opening,
new harvest policy, or trading model. Both new AgentConfig flags default false.
Keep all old heads and their sampling in place so the stochastic stream does not
shift when outputs are ignored. The candidate's executor alone changes; frozen
BC-E opponent and standard_mixed opening remain identical across arms.

## Arms

- baseline: original upkeep allocations;
- care: ignore care counts, care for already-fed animals with a future payable
  production before day 30. Banking happens AFTER tonight's production, so the
  next payable production must be at least day+2. Existing FEED scheduling stays;
- fertilizer: ignore fertilizer counts. Estimate incremental units over three
  days under current first-opportunity harvest behavior; reject existing active
  coverage, removed crops, unproductive ages, caps, and terminal benefits;
- combined: both options.

Fertilizer requires estimated added crop value > 1.25 times the observed
fertilizer price. This is an explicit experimental margin, NOT a fitted economic
optimum or a measured labor cost. Retained/home-produced fertilizer has an
opportunity cost. Existing affordability/debt controls handle implied purchases.
Ongoing forecasts assume future watering and collection between production
windows; realized execution can fall short. No new global fertilizer optimizer
or trading reservation policy is included.

One-shot productive WATER tasks depend on selected FERTILIZE tasks. Survival
WATER never waits on fertilizer: such applications are deferred/skipped.
Ongoing crops can be fertilized after watering, before midnight. Existing
maintenance and harvest task priorities are retained. Care/fertilizer task
sources and AgentConfig diagnostics identify the experiment.

## Running

Use the existing Kaggle environment and attached checkpoint datasets. Preserve
notebook accelerator and dataset metadata. Clone this branch using Kaggle
Secrets-backed Git authentication. Do not replace existing notebook state.

The evaluator requires the old PPO NPZ (and its original required sidecars) and
its compatible BC-E Torch checkpoint. Default history semantics are E_LEGACY;
do not override unless artifact provenance specifies another version.

Example, from the repository root, after binding actual checkpoint paths:

```bash
python -m tools.evaluate_stage25_upkeep \
  --checkpoint "$PPO_CHECKPOINT" \
  --e-checkpoint "$BC_E_CHECKPOINT" \
  --seeds 144368101 2112243121 \
  --master-seed 25 \
  --backend official \
  --variants baseline care fertilizer combined \
  --output-dir artifacts/local/stage25-upkeep-screen
```

This screen runs 16 complete games: two seeds, both seats, four arms. These seeds
come from previously inspected replays; this is an exploratory screen, not a
held-out promotion panel. The official adapter requires pinned 1.32.7 provenance.
`--backend fast` is a diagnostic option, not official promotion evidence.

The evaluator samples the PPO policy, unlike the existing deterministic eval
CLI. Its per-game/day random keys are stable across arms; master seed is encoded
in episode indices, since the adapter samples from request identifiers. This
is the existing JAX stochastic policy distribution, NOT the exact precomputed
Torch O-u10 personality stream. Keep seeds, order, master seed, model identity,
and opening fixed across comparisons. The opponent stays on original upkeep.

Fresh output directory required. Manifest includes source commit/dirty status,
tracked diff hash, checkpoint file hashes and configuration; each completed
game is saved immediately, with per-arm summaries and final paired deltas.
Run from a clean committed checkout for reproducible source identity. Keep runs
foregrounded. Failed/incomplete games stop the run; retain partial files and
rerun into a fresh directory after fixing the cause. No silent resume.

Inspect paired bank differences, margins/win outcomes, status anomalies,
manager intent/execution telemetry and land utilization in summaries. A tiny
positive mean is insufficient evidence. Expand promising arms on fresh seeds
and both seats before adopting defaults. No trained-model scores were available
when preparing this experiment: model artifacts are absent from the clone.
